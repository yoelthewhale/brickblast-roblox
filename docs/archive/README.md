# Archive

These are point-in-time snapshots from earlier in development (mostly Day10-Day43). They were accurate when written but are **not maintained** and should not be read as current truth about the game.

Kept for historical reference only — mainly useful if you want to see *why* a decision was made, or what an earlier design pass looked like, not *what's true now*.

| File | What it was |
| --- | --- |
| `DAY34_VISUAL_SPEC.md` | The visual design target for the Day34 toybox hub / puzzle UI pass |
| `Day41DesignTarget.md` | The design brief for moving Solo gameplay to full-viewport |
| `Day41StageVisualLayers.md` | How stage-based visual theming was scoped when first built |
| `ENVIRONMENT_VISUAL_AUDIT.md` | A Day10 audit of hub/world visual problems and the fixes made |
| `UI_CONTROL_AUDIT.md` | A Day43 audit of every player-facing button and what it did at the time |
| `ASSET_AUDIT.md` | A Day10 safety check confirming no third-party assets were imported |
| `UI_ICON_UPLOAD_MANIFEST.md` | A record of a rejected icon-pack pipeline attempt — do not use these packs |
| `PROJECT_TRACKER.md` | The original Day2-Day37 task tracker, imported from Tuesday.com. Superseded by GitHub Issues. |
| `TUESDAY_IMPORT.csv` | The raw CSV import that originally seeded the old project tracker |

For what's actually true right now, use:

- **GitHub Issues** + the **BrickBlast Development** project board — the real, current task tracker
- [`README.md`](../../README.md) — current status and tech stack
- [`AGENTS.md`](../../AGENTS.md) — current entry points and workflow rules
- [`docs/GAMEPLAY_RULES.md`](../GAMEPLAY_RULES.md) — current gameplay rules
